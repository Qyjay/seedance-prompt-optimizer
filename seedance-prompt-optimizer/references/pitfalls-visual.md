# 视觉类陷阱（V-1 ~ V-18）

每条都按 **症状 → 原因 → 修复 → prompt 模板** 的格式给出，命中后就地补救。

> V-1 ~ V-12 为旧版陷阱清单；V-13 ~ V-18 为依据火山引擎 PE 指南补充的新陷阱（九宫格 / 时间戳 HUD / 多人歧义断句 / 背景招牌文字 / 数字滚动 / 多人物多素材上限）。

---

## V-1 · 人物 ID 漂移

**症状**：生成的角色与参考图不一致；视频中途"换脸"；后续撞脸明星被审核拦截。

**原因**：人脸参考图的有效性不足。常见情况：
- 把人脸图与全身/半身姿态图、服装图、细节图合并在同一张图里。
- 人脸区域占整张图比例过小，模型提取人脸特征权重不够。

**修复**：

1. 把人脸区域**单独裁剪**为一张特写图，作为独立参考图（精确裁剪，尽量只保留面部）。
2. **越需要精准参考的素材，放在 prompt 越前面**。
3. **不建议用三视图或多视图**作为人物参考。一张大头照 + 一张全身照即可。
4. 在 prompt 中分层指代：

```
主体1 的面部特征参考 @图片1（大头照），妆造参考 @图片2（全身照）
```

## V-2 · 避免生成字幕

**症状**：本不该有字幕的视频，模型自己生成字幕，且文字常有错误。

**修复**（无法 100% 避免，只能降低概率）：

1. prompt 加约束：`保持无字幕，避免画面生成字幕`。可降至 60%→30%。
2. 去除参考素材中不必要的文字（用 Seedream/Seedance 擦除）。
3. **横屏生成（16:9）字幕概率明显低于竖屏（9:16），可降至 < 10%**。
4. 减少一次生成视频中的分镜数。
5. 后期补救：用 AI MediaKit 字幕擦除工具消除已生成的字幕。

**Prompt 模板**：

```
[原 prompt 内容]
保持无字幕，避免画面生成字幕。
时长：4秒，比例：16:9
```

---

## V-3 · 避免生成 logo / 水印

**症状**：指令中没提水印，但生成的视频带其他平台 logo（B 站、芒果 TV 等）。

**修复**：在 prompt 中明确：

```
不要生成 logo，不要生成水印。
```

---

## V-4 · 风格漂移

**症状**：参考图风格偏接近真人，或多张参考图中有部分偏写实，没特别强调风格保持时，模型生成偏写实风格。

**修复**：

1. **明确风格关键词**：`3D 国漫 CG 仙侠风格`、`2D 日漫风格`等。
2. 如需更精准控制，**先把参考图转换成目标风格**（用 Seedream 等），再用风格化后的图生视频。

**Prompt 模板**：

```
3D 国漫 CG 仙侠风格。[原 prompt 内容]
```

---

## V-5 · 有规律的闪烁 / 横纹

**症状**：有规律的闪烁、横纹均匀分布在整个视频中，深色色块画面尤为明显。

**修复**：已上线新算法解决。如客户对画质问题反应强烈，可拉 oncall 提供 task id 确认是否暗水印导致；如确定是，可提供 ep 跳过暗水印环节。

---

## V-6 · 延长视频衔接处跳变

**症状**：用"延长模式"生成的视频拼接后，在衔接处出现画面跳变、回退。

**修复**：

- 后期剪辑：对前段视频末尾删 6 帧，对后段视频开头删 1 帧。
- 或用**转场切镜**结尾，用切镜代替无缝衔接。

---

## V-7 · 双胞胎问题

**症状**：画面中出现两个几乎一模一样的人物主体。

**修复**：

1. **不建议使用三视图或多视图**作为人物参考。
2. 参考主体定义规范，每次涉及主体时**明确指代**。
3. 在 prompt 中明确：

```
视频全程不要在同一画面中复制相同人物，不要多人同脸。
```

4. 精简 prompt，避免冗余的多视图描述。

---

## V-8 · 视频延长画质劣化

**症状**：把模型生成的视频作为原始视频做延长续写，画质会劣化；多次续写劣化叠加，尤其在人脸出现斑驳色块。

**修复**：

1. 把原始视频先用 Seedance 2.0 转化为**白模视频**：

```
将@视频1 转化为白模视频：保留所有人物的姿态和动作，但移除所有纹理、色彩、面部细节，仅保留白色 3D 几何模型，背景纯白。
```

2. 用白模视频 + 高清人物图 + 高清场景图作为输入：

```
向前延长@视频1（白模），人物形象严格参考@图片1（高清人脸特写），场景参考@图片2（高清场景图），生成 [新内容]。
```

## V-9 · 数字滚动特效

**症状**：模型生成的数字滚动效果有明显无序跳变感，提示词约束无效。

**修复**：增加正确的数字滚动效果**参考视频**。

```
参考@视频1 的数字滚动特效，生成 [新场景] 中数字从 0 滚动到 100 的画面，保持滚动节奏一致。
```

---

## V-10 · 参考人物超过 4 人

**症状**：参考人物超过 4 人时，模型表现不稳定，可能少人、多人、出现重复人物。

**修复**：先用图模型（如 Seedream）生成多张图，每张图人物数 ≤ 4，再用这多张图生视频。

---

## V-11 · 胡言乱语

**症状**：增加额外台词、增加听不懂的台词、重复台词。

**修复**：

1. **合理缩短**生成视频的时长。
2. 业务允许时，**竖屏改横屏输出**也能降低胡言乱语概率（约 70% → 30%）。

## V-12 · 第一人称漂回第三人称（POV Drift）

**症状**：

- prompt 写了"第一人称视角"，结果画面里出现一个对着镜头说话的人；
- 写了"第一人称走路"，结果是从背后跟拍的第三人称；
- 第一人称视频前 2 秒还像 POV，到第 3 秒突然切到第三人称跟拍。

**原因**：

1. **只写了"第一人称视角"几个字**，没有命名具体摄像机设备（iPhone 前置 / GoPro 胸挂 / 行车记录仪 / FPV）—— 模型对"第一人称"语义模糊。
2. **画面里没有肢体锚点**（双手、双脚、方向盘、持枪小臂等）—— 模型 90% 会回退到浮空第三人称。
3. **同时描写了主体的脸部特征**（"长方脸、剑眉、薄唇"）—— 触发模型把脸渲染到镜头前，破坏第一人称感。
4. 动作 beat 太多太快，模型放弃 POV 选了更稳定的第三人称跟拍。

**修复**（按以下顺序套）：

1. 不要单独写"第一人称视角"，改为：

```
主观镜头 POV，[具体设备：iPhone 前置摄像头 / GoPro 胸挂 / 行车记录仪 / 无人机 FPV]，
画面下沿可见「主体1」的[肢体锚点：双手 / 双脚 / 方向盘 / 持枪小臂]。
```

2. **删除**对主体面部 / 五官的所有描写（"观众就是这张脸"，POV 不需要描写自己长什么样）。
3. 动作严格按 1–2 beat/秒分段。
4. 加命名光源 + 配色锚点。
5. 结尾固定加：

```
单镜连续，无切镜、无变焦、自然头部晃动。
保持无字幕，不要生成 logo，不要生成水印。
```

**Prompt 修复模板**：

```
主观镜头 POV，行车记录仪安装在挡风玻璃内侧，黎明时分车辆驶过住宅街。
画面下沿是两只手放在皮革方向盘上。
beat 1：方向盘缓慢左打 →
beat 2：方向盘回正 →
beat 3：前方一名晨跑者横穿，车温和减速。
冷色黎明蓝光，路边树丛之间漂着低雾。配色：石板蓝、沥青灰、柔白。
画质如真实行车记录仪：固定锁死机位，无任何抖动。
单镜连续，无切镜、无变焦。
保持无字幕，不要生成 logo，不要生成水印。
时长：5秒，比例：16:9
```

**完整方法论与 5 套 Recipe**：见 `references/first-person-pov.md`。

## V-13 · 九宫格参考图无效

**症状**：把多张角色 / 道具 / 场景图拼成九宫格当一张参考图输入，模型对某些小图参考不到位 —— 角色细节漂移、道具丢失、场景错位。

**原因**：九宫格融合了太多小图后，每张小图的有效分辨率与权重都被稀释；模型难以单独锁定其中某一格。

**修复**：将九宫格**拆分为若干独立参考图**，再分别引用。

**Prompt 模板**：

```
❌ 错误：[图1] 为九宫格参考（包含人物、道具、场景）...

✅ 正确：
[图1] 为角色"X"的面部参考。
[图2] 为角色"X"的全身参考。
[图3] 为关键道具"嗨皮表"参考。
[图4] 为场景"咖啡店"参考。
```

## V-14 · 时间戳 / HUD 叠加格式错误

**症状**：要求叠加时间戳、监控编号、HUD 文字，但生成结果格式不稳定 —— 时而出现、时而消失，或字体 / 位置 / 格式变化。

**原因**：模型对"叠加文字"这种细粒度持续元素的稳定性较弱，需要显式锁定位置、颜色、格式、稳定性。

**修复**：必须明确 **位置 + 颜色 + 字体格式 + 稳定性约束** 四件套。

**Prompt 模板**：

```
在整个视频的左上角，稳定叠加一行白色等宽字体文字，
格式为 'CAM-03 YYYY/MM/DD hh:mm:ss'。
该文字在视频播放期间保持固定不变，无闪烁、无格式变化。
```

## V-15 · 多人场景人物数量出错（歧义断句）

**症状**：多次生成的视频中人物数量不固定（说好的 4 人，时而 3 人时而 5 人），人物位置错乱。

**原因**：提示词中数字与人物名连写产生歧义断句。例如：

> "美女3 位于画面左下后景，美女4 位于..."

模型可能解析为"美女 3 位"（数量）+"于画面左下后景"（位置），导致每次理解人数都不同。

**修复**：**用字母替代数字**作为人物编号，或在数字后插入清晰停顿词。

**Prompt 模板**：

```
❌ 错误：美女3 位于画面左下后景，美女4 位于画面右上前景。

✅ 正确：美女C 位于画面左下后景，美女D 位于画面右上前景。
```

## V-16 · 背景招牌 / 品牌文字漂移

**症状**：要求画面出现某品牌门头（如"瑞幸咖啡"），生成结果文字模糊、错字、变形；或不需要文字时画面自己加了一堆乱码招牌。

**原因**：

- 模型生成长串文字（尤其是品牌名）准确率本就不高。
- 默认状态下模型倾向于在街景 / 商场 / 室内场景中"补"招牌文字。

**修复**：

1. **需要出现**指定品牌时：提供清晰的招牌参考图，并在 prompt 中绑定。
2. **不需要文字**时：显式约束。

**Prompt 模板**：

```
✅ 需要出现：背景招牌文字参考 [图N]，严格还原"瑞幸咖啡"标志与字体颜色。

✅ 不需要出现：背景不要出现任何文字、招牌、品牌 logo。
```

> 复杂招牌建议后期叠加：先生成无文字干净背景，再用剪辑工具加文字。

## V-17 · 数字滚动 / 倒计时 / 进度条特效

**症状**：金额跳动、倒计时、进度条等数字滚动效果不稳定 —— 数字无序跳变、方向错误、节奏不对。

**原因**：数字滚动属于细粒度持续运动，仅靠文字约束无法精确控制节奏与方向。

**修复**：**必须提供一段"正确节奏"的参考视频**，在 prompt 中绑定节奏与方向。

**Prompt 模板**：

```
参考 [视频N] 的数字滚动节奏和方向，生成 [新场景] 中数字从 0 滚动到 100 的画面，
保持滚动节奏、方向、字体粗细一致。
```

⚠️ 这是当前提升数字滚动效果良品率的关键手段，单靠文字几乎无法稳定。

## V-18 · 多人物 / 多素材数量上限

**症状**：

- 多人场景人物超过 4 人时，模型表现不稳定（少人 / 多人 / 重复人 / ID 漂移）。
- 一次性塞入超过 5 个参考素材时，模型理解混乱。

**原因**：多模态绑定有上限，参考素材越多权重稀释越严重。

**修复**：

1. **单次生成的人物 ≤ 4 人**。
2. **参考素材总量 ≤ 4–5 个**。
3. 如需更多人物 / 素材，采用**分镜拆段 + 后期合成**：
   - 先用图模型（Seedream）生成多张图，每张图人物 ≤ 4。
   - 再用这些图分别生视频，最后剪辑合成。
4. 多人场景必须配合 V-15 的字母编号规范，避免歧义断句。

**Prompt 模板**：

```
❌ 一次塞 7 个角色 + 5 张参考图 → 拆为 2 段：

段 1：[图1][图2] + 角色A B C D
段 2：[图3][图4] + 角色E F G
后期剪辑合成。
```
